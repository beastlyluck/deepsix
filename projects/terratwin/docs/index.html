TerraTwin notes

Closed-loop climate for a vertical farm. The learner is fitted Q-iteration on facility-wide features. The truth file is config/facility.toml.

Reward

r = w_y · yield(PPFD, T, EC)
  − w_e · (kWh_light + kWh_mist) · tariff
  − w_d · mean(I)
  − w_ℓ · fraction of trays outside limits

Yield saturates in PPFD and has Gaussian bands on temperature and EC. Disease is not something the policy “cures” on a 15-minute step — it is a tax on letting RH sit high next to an infected neighbour. Weights are in the toml so a grower can retune without a retrain of the feature code.

Sensor schema

One row per tray per 15 minutes: tower, layer, slot, temp_c, rh, ec_ms, ppfd, infected. Neighbours are face-adjacent on the same slot. The stack bias (floor warmer) is applied in the climate step, not as a stored column — if you persist it, the learner will treat it as a controllable.

FQI features are facility means, a 90th percentile on temp and RH, and mean infection. Per-tray actions are out of scope.

Lightweight cluster

docker build -f deploy/Dockerfile -t terratwin-loop:local .
kubectl apply -f deploy/k8s.yaml
# or
systemctl enable --now terratwin-loop   # deploy/controller.service

One replica. The loop is the product. The cluster only restarts it. Weights come from outputs/q_weights.npy after python main.py.
